# **P2: Form a Valid Arithmetic Equation — Implementation Plan**

**Language:** SWI-Prolog 9.x\
**File:** `code/id_q2.pl`\
**Goal:** Generate valid arithmetic equations, format them canonically, and collect all distinct equations in sorted order.

Implement and test **one predicate at a time**, following the assignment's AI decomposition rule.

## **1. Predicate-by-predicate plan**

| Step | Predicate             | Responsibility                                                                                                                 |
| ---- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1    | `split_numbers/3`     | Split the input into two nonempty consecutive lists, preserving order. These become the left and right sides of `=`.           |
| 2    | `expression/3`        | Recursively generate every binary expression tree for a list of numbers, returning its tree and evaluated integer value.       |
| 3    | `apply_operator/4`    | Evaluate `+`, `-`, `*`, `/`. Permit division only when the divisor is nonzero and the division is exact.                       |
| 4    | `precedence/2`        | Assign operator precedence: `+`, `-` lower than `*`, `/`.                                                                      |
| 5    | `format_expression/2` | Convert expression trees into canonical strings, using parentheses based on precedence, associativity and operand position.    |
| 6    | `generate_equation/2` | Combine splitting, expression generation, equality checking and formatting to produce one valid equation through backtracking. |
| 7    | `all_equations/2`     | Collect every generated equation, eliminate duplicates and sort using `sort/2`.                                                |
| 8    | `count_equations/2`   | Return the length of the list produced by `all_equations/2`.                                                                   |

The predicate names and helper signatures are suggested implementation choices; only the public predicates are specified by the assignment.

## **2. Key implementation rules**

### **Expression trees**

- Preserve the original number order and use every number exactly once.
- A leaf represents one number; an internal node represents a binary operator.
- Generate all possible binary parenthesizations, not just left-associative expressions.
- Do not allow unary minus or concatenation of numbers.
- Compute values recursively, including negative intermediate results.

### **Exact division**

- Never divide by zero.
- Require zero remainder for every division operation.
- Do not allow fractional intermediate results, even if the final answer is an integer.

### **Canonical formatting**

- No spaces; return an SWI-Prolog **string**, not an atom.
- Left child: parentheses only when its operator has lower precedence.
- Right child: parentheses when its operator has equal or lower precedence.
- Never parenthesize a single number.
- Preserve different expression-tree structures as distinct strings.

### **Collecting equations**

- Use Prolog backtracking to enumerate valid expression combinations.
- Ensure the left and right evaluated values are equal.
- Use `findall/3` and `sort/2` to collect unique equations.
- Return `[]` when there are no solutions.

## **3. Tests to prioritize**

| Input       | Expected result                |
| ----------- | ------------------------------ |
| `[4,2,5,3]` | Exactly 7 equations            |
| `[2,3,4]`   | No equations; generation fails |
| `[2,4,8]`   | `["2*4=8"]`                    |

For `[4,2,5,3]`, verify the complete sorted output:

```
["4*2-5=3",
 "4*2=5+3",
 "4-2=5-3",
 "4/2=5-3",

 "4=2+(5-3)",
 "4=2+5-3"]
```

### **Additional edge cases**

| Test        | What to verify                             |
| ----------- | ------------------------------------------ |
| `[]`, `[5]` | Fail cleanly for `generate_equation/2`     |
| `[0,0]`     | Valid `0=0`, without division by zero      |
| `[1,1]`     | Valid equality with repeated input values  |
| `[3,5,2]`   | Negative intermediate results can be used  |
| `[1,2,3,4]` | Different parenthesizations are considered |
| `[8,4,2]`   | Exact division and operator combinations   |
| `[0,2,0]`   | Zero divisors never cause exceptions       |

Also test formatting independently using the assignment examples: `8/4*2` versus `8/(4*2)`, `1-2-3` versus `1-(2-3)`, and `1+2+3` versus `1+(2+3)`.
